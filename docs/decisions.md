# Implementation decisions

## 2026-10-17 — Phase 2

- The repository began with the v2 build plan only; no Phase 1 app, status, prototype HTML, or fixtures existed. Added the prerequisites needed to make Phase 2 runnable: pinned npm dependencies, Next App Router/TypeScript/Tailwind, Supabase invite-only sign-in helpers and cookie refresh, PostgreSQL/Drizzle schema and versioned SQL migrations, synthetic clients, admin client management, and dashboard empty states. No Phase 3 metrics or later integrations were implemented.
- Meta and Indeed require their Appendix B headers. Header order/outer whitespace/BOM may vary; missing, additional, duplicate headers and inconsistent column counts are errors. All provided numeric values are validated; optional blank/dash values remain missing. Money uses decimal.js and PostgreSQL numeric. Unavailable Meta link-click totals stay null, never a false zero. Reach/frequency/unique clicks are not summed.
- Original raw text is stored with each normalized row. DriverHub dates are calendar dates; datetime text remains in `raw`. No timezone is inferred from export text. Multiple values are split on tabs into `values`, preserving annotations. Both tab joins and +N annotations populate `ambiguous_fields`; normalized ambiguous fields are null. Same-name candidates remain distinct rows.
- Preview parsing stores only its summary and metadata in `imports`; normalized rows are inserted at confirmation after reparsing the private original and checking its SHA-256. Invalid exports have `failed` status and cannot activate. Cancelling a failed/valid preview deletes its record and file, retaining only an audit event. The same hash cannot be imported again until that preview is cancelled.
- PostgreSQL transaction-scoped advisory locks serialize each client/source lifecycle, backed by a partial unique index allowing only one active import. Confirmation, normalized-row inserts, supersession, and audit are one transaction. The browser must supply the active ID it reviewed; stale confirmations fail. Revert changes status only and never copies/adds rows.
- Actual XLSX decompression is streamed and bounded before ExcelJS loads values. Formula/macro/external-link/rich-text/hyperlink/error cells are rejected rather than using a potentially stale cached result. Declared ZIP sizes alone are not trusted.
- Limits use binary units: 10 MiB upload, 50,000 data rows, 100 MiB inflated archive, 2,000 entries. The action envelope allows 11 MiB; the file itself is checked again server-side.
- Private disk storage is intended for development/persistent private volumes. Hosted Supabase uses a private bucket verified at runtime and a server-only service key. No public URLs or signed download URLs are emitted. Cancellation commits DB deletion before removing its file: a storage deletion outage can leave a private orphan requiring operator cleanup, but cannot remove an active import. Storage and SQL cannot share a distributed transaction.
- Auth is tested through a synthetic Supabase HTTP fixture, not a production auth bypass. Database lifecycle tests use actual PostgreSQL 17.11. No claims of live Supabase/vendor connectivity or real-file reconciliation are made.
