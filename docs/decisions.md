# Implementation decisions

## 2026-10-17 — Phase 2

- The repository began with the v2 build plan only; no Phase 1 app, status, prototype HTML, or fixtures existed. Added the prerequisites needed to make Phase 2 runnable: pinned npm dependencies, Next App Router/TypeScript/Tailwind, Supabase invite-only sign-in helpers and cookie refresh, PostgreSQL/Drizzle schema and versioned SQL migrations, synthetic clients, admin client management, and dashboard empty states. No Phase 3 metrics or later integrations were implemented.
- Meta and Indeed require their Appendix B headers. Header order/outer whitespace/BOM may vary; missing, additional, duplicate headers and inconsistent column counts are errors. All provided numeric values are validated; optional blank/dash values remain missing. Money uses decimal.js and PostgreSQL numeric. Unavailable Meta link-click totals stay null, never a false zero. Reach/frequency/unique clicks are not summed.
- Original raw text is stored with each normalized row. DriverHub dates are calendar dates; datetime text remains in `raw`. No timezone is inferred from export text. Multiple values are split on tabs into `values`, preserving annotations. Both tab joins and +N annotations populate `ambiguous_fields`; normalized ambiguous fields are null. Same-name candidates remain distinct rows.
- Preview parsing stores only its summary and metadata in `imports`; normalized rows are inserted at confirmation after reparsing the private original and checking its SHA-256. Invalid exports have `failed` status and cannot activate. Cancelling a failed/valid preview deletes its record and file, retaining only an audit event. The same hash cannot be imported again until that preview is cancelled.
- PostgreSQL transaction-scoped advisory locks serialize each client/source lifecycle, backed by a partial unique index allowing only one active import. Confirmation, normalized-row inserts, supersession, and audit are one transaction. The browser must supply the active ID it reviewed; stale confirmations fail. Revert changes status only and never copies/adds rows.
- Actual XLSX decompression is streamed and bounded before ExcelJS loads values. Formula/macro/external-link/rich-text/hyperlink/error cells are rejected rather than using a potentially stale cached result. Declared ZIP sizes alone are not trusted.
- Limits use binary units: 10 MiB upload, 50,000 data rows, 100 MiB inflated archive, 2,000 entries. The action envelope allows 11 MiB; the file itself is checked again server-side.
- Private disk storage is intended for development/persistent private volumes. Hosted Supabase uses a private bucket verified at runtime and a server-only service key. No public URLs or signed download URLs are emitted. Cancellation commits DB deletion before removing its file: a storage deletion outage can leave a private orphan requiring operator cleanup, but cannot remove an active import. Storage and SQL cannot share a distributed transaction.
- Auth is tested through a synthetic Supabase HTTP fixture, not a production auth bypass. Database lifecycle tests use actual PostgreSQL 17.11. No claims of live Supabase/vendor connectivity or real-file reconciliation are made.

## 2026-10-17 — Phase 3

- Updated the clean checkout to the merged Phase 2 foundation (`e9f3c9f`) before implementing reporting. No earlier-phase app was recreated. The referenced HTML prototype is still absent; the dashboard extends the existing Wayfind teal/white shell and the sections specified in the plan.
- Pure reporting functions use decimal.js with 40-digit precision and return source/period/definition/null-reason metadata. Money stays decimal, rates are recomputed from sums, and unknown Meta link-click results make dependent metrics unavailable. Table totals follow the visible filters; header spend includes the complete active source import. No combined spend across mismatched periods is offered.
- Native semantic HTML tables and server GET filters keep reporting data server-side and preserve filters in URLs without adding a client table dependency. Horizontal regions are keyboard focusable; metric definitions are exposed on focus/hover and KPI details. No charts imply daily data or dated funnel transitions.
- The reporting service uses repeatable-read, read-only transactions so import activation/revert cannot mix old and new rows in a response. Client-specific loading boundaries replace pending content during navigation. Candidate links retain their snapshot ID, plus stage mapping for configurable stages, so count-to-list behavior remains exact after subsequent changes. Historical snapshots are labelled, client ownership is checked, and original row numbers provide stable pagination. With the existing 50k-row import limit and fewer than five staff, candidate filtering runs server-side over one snapshot; only 25 records are rendered per list page.
- Interview and onboarding status lists are admin-editable in client settings and audited; saving merges the stages key without replacing other settings. The default labels remain provisional. Signed/rejected/start rules remain separate and unambiguous dates are counted even when an unrelated status needs review.
- Meta delivery filters use the exported delivery string (`active`, `ended`, `completed`) and known end dates relative to the report end, not today's wall clock. Other states remain visible under All. Name parsing is display-only and conservative, with raw names retained.
- Phase 4 channel performance, alerts, manual budgets, account context and print export were not implemented.

## 2026-10-17 — User-approved local single-owner direction

- The user confirmed a one-person business and explicitly authorized replacing hosted staff access with a local app. The app now has no login, roles or invitations; Supabase/PostgreSQL dependencies and hosted auth routes were removed. Provider approvals for future integrations remain separate and unverified. [local-app-plan.md](local-app-plan.md) is the current architecture and scope authority.
- Chose embedded SQLite via the file-only libSQL driver and Drizzle to retain asynchronous transactions and most existing import/reporting code. No hosted libSQL/Turso service is used. Monetary/count fields use text, JSON fields use JSON-encoded text, IDs are generated locally, and foreign keys plus partial unique indexes preserve client/source integrity. Transactions are serialized within the one serving process.
- The app binds only to IPv4 loopback. Both proxy and server entry helpers check the exact local host/port, same origin and browser request context. No permissive CORS policy or remote-access option was introduced. A fixed audit provenance label replaces user IDs; it is not an authentication bypass.
- Database/originals live together in an OS-specific private data directory, separate from code/builds. A maintained filesystem-lock package gives the actual serving process exclusive ownership of that directory; launch/offline maintenance share it. Unexpected-shutdown recovery waits up to two minutes.
- Added Windows and macOS/Linux launchers, optional browser opening and build fingerprints. A source/dependency/Node-major mismatch requires a rebuild, so an old hosted/auth build cannot silently launch after an update. Node installation remains a setup-helper prerequisite; this is not a packaged executable installer.
- Backups use a consistent SQLite snapshot plus verified copies of every referenced original under the same transaction queue. Manual backups are available in the browser; daily automatic backups run on startup and are checked hourly. Keep seven automatic copies, preserve manual/pre-restore copies, and require external copies for protection against losing the machine. Restore is an offline command with an explicit confirmation flag, validates and stages all bytes, and preserves the old complete store even if it is corrupt.
- The old PostgreSQL migration was archived; no real deployment/data was available for a verified database conversion. Existing hosted installations must retain originals/backups and recreate clients/settings/re-upload reports before retiring that copy. No hosted database is deleted or modified.
- Future provider adapters can reuse the pure parsers, reporting and activation lifecycle. Future refresh jobs run locally while the computer/app are awake; credentials should use the OS credential vault when implemented. No API credentials, live integration, background vendor sync or fictitious connection was added.
